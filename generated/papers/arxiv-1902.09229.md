## 主張

出典のリンクは原論文PDFの該当ページを開く。リンクにカーソルを合わせると原文の引用が表示される。

- **c1** Core assumption (latent classes): similar points x, x+ are i.i.d. draws from the same class distribution D_c for a class c drawn from rho, and negatives are drawn from the marginal; i.e. the pair is conditionally independent given the latent class. Classes may overlap and no functional form is assumed for D_c or rho.([Section 2 (Semantic Similarity), p.2](https://arxiv.org/pdf/1902.09229v1#page=2 "To formalize similarity, we assume similar data points x, x+ are i.i.d. draws from the same class distribution Dc for some class c picked randomly according to measure ρ."))
- **c2** The guarantees depend on downstream tasks being made of the same latent classes, with the same class distributions, as the unlabeled data; downstream classes are assumed uniformly distributed in the main-paper theorems (general case in the appendix).([Section 2 (Supervised Tasks), p.2](https://arxiv.org/pdf/1902.09229v1#page=2 "A key subtlety in this formulation is that the classes in downstream tasks and their associated data distributions Dc are the same as in the unlabeled data."))
- **c3** Price of negative sampling (class collision): because the negative can come from the same class as the positive pair, the unsupervised loss is at least tau (the probability that two sampled classes coincide), and without further assumptions on f it can be far from tau, making the Theorem 4.1 bound useless; the authors then control this term with an intraclass-deviation quantity s(f) (Theorem 4.5).([Section 4.2, p.5](https://arxiv.org/pdf/1902.09229v1#page=5 "In general, without any further assumptions on f, Lun(f) can be far from τ, rendering the bound in Theorem 4.1 useless."))
- **c4** Limitation: the ideal guarantee (competing with the best supervised representation in the class F) is shown not to hold, with two counterexamples attributed to the algorithm rather than the analysis; contrastive learning will not always work when the only guarantee is that F can make the supervised loss small.([Section 5.1, p.5](https://arxiv.org/pdf/1902.09229v1#page=5 "Hence, contrastive learning will not always work when the only guarantee we have is that F can make Lsup small."))
- **c5** A weaker, competitive bound (Corollary 5.1.1, for the mean classifier) holds under additional assumptions: representations that are concentrated within classes (sub-Gaussian in every direction) and a mean classifier with good (high-margin) performance.([Introduction, p.2](https://arxiv.org/pdf/1902.09229v1#page=2 "However, if the representations are well-concentrated and the mean classiﬁer (Deﬁnition 2.1) has good performance, we can show a weaker version of the ideal result (Corollary 5.1.1)."))
- **c6** Contrary to the belief that more negatives always help, the analysis shows that larger k can hurt: with rho close to uniform and k = Omega(|C|), frequent class collisions can prevent learning the supervised-optimal representation (the coefficient of s(f) grows with k).([Section 6.2, p.7](https://arxiv.org/pdf/1902.09229v1#page=7 "However, we ﬁnd that such a phenomenon does not always hold for contrastive learning – larger k can hurt performance for the same inherent reasons highlighted in Section 5.1, as we illustrate next."))
- **c7** Controlled experiments (CIFAR-100 with VGG-16, Wiki-3029 with a GRU) simulate the assumed data model by sampling similar pairs/blocks from the same labelled class and negatives at random, and compare with supervised training of the same architecture; the main evaluation is average k-wise classification with the mean classifier, while full multiclass accuracy (TOP-R) is reported but not covered by the theory.([Section 8.1, p.8](https://arxiv.org/pdf/1902.09229v1#page=8 "Contrastive learning was done using our objectives (5), and compared to performance of standard supervised training, with both using the same architecture for representation f."))
- **c8** Scope: the framework ignores efficient minimization of the losses and studies only the relations between their minimizers and the sample complexity needed to generalize; the authors call it a first cut.([Conclusion, p.9](https://arxiv.org/pdf/1902.09229v1#page=9 "The framework currently ignores issues of efﬁcient minimization of various loss functions, and instead studies the interrelationships of their minimizers as well as sample complexity requirements for training to generalize, while clarifying what generalization means in this setting."))
