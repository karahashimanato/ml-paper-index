- **c1** Method: TPOT uses genetic programming (as implemented in DEAP) to evolve both the sequence of pipeline operators and each operator's parameters, maximizing the classification accuracy of the pipeline; changes can modify, remove or insert sequences of operators. At the end of a run the single best pipeline ever found (by accuracy) is used.([Section 3.3, p.4](https://arxiv.org/pdf/1603.06212v1#page=4 "In TPOT, we use GP to evolve the sequence of pipeline operators as well as each operator’s parameters (e.g., the number of trees in a random forest or the number of feature pairs to select during feature selection) to maximize the classiﬁcation accuracy of the pipeline."))
- **c2** Pipeline representation: pipelines are trees whose leaves are copies of the input data and whose nodes are operators (preprocessing, decomposition, feature selection, models), with a combination operator to merge copies; when data passes through a modeling operator, the newest classifier's predictions override earlier ones and earlier predictions are kept as a new feature, allowing arbitrary (including stacked) pipeline structures.([Section 3.2, p.3](https://arxiv.org/pdf/1603.06212v1#page=3 "Each time a data set is passed through a modeling operator, the resulting classiﬁcations are stored such that the most recent classiﬁer to process the data overrides any previous predictions, and the earlier classiﬁer’s predictions are stored as a new feature."))
- **c3** Fitness evaluation split: data is divided into stratified 75% training and 25% testing sets and pipelines are evaluated by classification accuracy on the testing set; the Results section reports balanced accuracy on 25% holdout sets (figure captions call these 'balanced cross validation accuracies on the holdout set', over 30 data sets or 30 cross-validation divisions). A validation split separate from the set used for GP fitness, or a discussion of overfitting that set, was not found in the text (searched for 'validation', 'overfit', 'holdout', 'cross').([Section 3.3, p.4](https://arxiv.org/pdf/1603.06212v1#page=4 "In this paper, TPOT pipelines are evaluated based on their classiﬁcation accuracy on the testing set."))
- **c4** TPOT-Pareto optimizes two objectives, maximizing classification accuracy and minimizing pipeline complexity (total number of operators); since no solution is globally optimal for both, it keeps a Pareto front and selects pipelines for reproduction with NSGA-II.([Section 3.3, p.4](https://arxiv.org/pdf/1603.06212v1#page=4 "we maintain a Pareto front in TPOT-Pareto and select the pipelines for reproduction according to the NSGA-II selection strategy"))
- **c5** Data: 360 simulated GAMETES data sets (12 genetic models; 3 heritabilities x 4 sample sizes from 200 to 1600 x 30 replicates; 100 SNPs of which 8 predictive, with purely epistatic interactions and no main effects) and 9 UCI data sets that the authors describe as hand-picked.([Section 3.5, p.4](https://arxiv.org/pdf/1603.06212v1#page=4 "To further demonstrate TPOT’s capabilities, we evaluate it on 9 hand-picked benchmark supervised learning data sets from the well-known UC-Irvine Machine Learning Repository [12]."))
- **c6** Controls: a random forest with 500 trees (a basic analysis with a state-of-the-art model) and TPOT-Random, which randomly generates the same number of pipelines, to test whether guided search is useful.([Section 4, p.7](https://arxiv.org/pdf/1603.06212v1#page=7 "The second control, TPOT-Random, is a version of TPOT where the same number of pipelines are randomly generated, which is meant to explore whether guided search is useful for pipeline optimization."))
- **c7** On the GAMETES data, all TPOT versions performed more or less the same on average in most cases, which the authors say suggests guided search may not be vital because random search generally performs as well; TPOT-Pareto tended to be more consistent (lower variance). On UCI data TPOT-Random also typically performed as well as guided search.([Section 4, p.7](https://arxiv.org/pdf/1603.06212v1#page=7 "This result suggests that guided search may not be vital for the automated design of pipelines because random search generally performs as well as guided search."))
- **c8** Pipeline bloat and cost: randomly generated pipelines tend to be needlessly complex (6 operators on average vs. 4 for TPOT and 2 for TPOT-Pareto, per the text), are slower, and on the larger Hill-Valley and spambase data sets no TPOT-Random replicate finished within 120 hours, whereas all TPOT and TPOT-Pareto replicates finished the same number of evaluations in under 48 hours.([Section 4, p.7](https://arxiv.org/pdf/1603.06212v1#page=7 "Furthermore, even though TPOT-Random pipelines perform nearly as well as regular TPOT pipelines, TPOT-Random pipelines tend to be needlessly complex and contain 6 pipeline operators on average (Figure 5)."))
- **c9** Stated limitation: TPOT is in early development, is still fairly slow on large data sets and often needs several hours (if not days); the authors plan to seed the population (e.g. with auto-sklearn) and bias mutation/crossover with a learning system.([Section 5, p.8](https://arxiv.org/pdf/1603.06212v1#page=8 "In particular, TPOT is still fairly slow on large data sets and often requires several hours (if not days) to properly analyze a large data set."))
