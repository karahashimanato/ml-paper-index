## 主張

出典のリンクは原論文PDFの該当ページを開く。リンクにカーソルを合わせると原文の引用が表示される。

- **c1** Relation to B&B: ML is used to configure B&B, learning a weighting of existing partitioning (variable selection) procedures for the instance distribution at hand from sample instances; B&B itself is unchanged.([Abstract, p.1](https://arxiv.org/pdf/1803.10150v2#page=1 "We show how to use machine learning to determine an optimal weighting of any set of partitioning procedures for the instance distribution at hand using samples from the distribution."))
- **c2** Guarantee type: sample complexity bounds ensuring that empirical performance (e.g. tree size) over sampled instances nearly matches expected performance on the unknown instance distribution; the authors call these the first such guarantees for tree search configuration.([Abstract, p.1](https://arxiv.org/pdf/1803.10150v2#page=1 "These guarantees bound the number of samples sufficient to ensure that the empirical performance of an algorithm over the samples nearly matches its expected performance on the unknown instance distribution."))
- **c3** Assumptions: an unknown distribution over MILPs with sample access, a cap on the cost range (e.g. tree size capped at kappa), instances over n binary variables, a tree-constant cost function, and everything in tree search except variable selection (e.g. node selection) held fixed.([Section 3, p.8](https://arxiv.org/pdf/1803.10150v2#page=8 "Throughout the remainder of this paper, we assume that all aspects of the tree search algorithm except the variable selection policy, such as the node selection policy, are fixed."))
- **c4** Worst-case bound for path-wise scoring rules (a class including the most fractional, product and linear scoring rules but not pseudo-cost or reliability branching): for a convex combination of two path-wise rules with a tree-constant cost, over instances with n binary variables and a cost range capped at kappa, the number of samples sufficient for (epsilon, delta)-learning grows only quadratically with the number of variables (pseudo-dimension O(n^2), Theorem 3.7); for d arbitrary scoring rules (Section 3.3.2) the bound instead depends on the tree-size limit imposed on B&B.([Section 3.3, p.11](https://arxiv.org/pdf/1803.10150v2#page=11 "In this case, the number of samples is surprisingly small given the complexity of these problems: it grows only quadratically with the number of variables."))
- **c5** Impossibility result for data-independent tuning (Theorem 3.1): for the mixing parameter mu in [0, 1] of two specific scoring rules (the min and the max of the objective-value changes of the two children), with cost = B&B tree size, for any discretization of [0, 1] there exists an infinite family of distributions over MILPs with n variables (n even, n >= 6) such that every parameter in the discretization gives expected tree size exponential in n, while infinitely many other parameters (an interval (a, b) with 1/3 < a < b < 1/2) give constant-size trees with probability 1; the authors prove it holds for any node selection policy.([Section 3.2, p.9](https://arxiv.org/pdf/1803.10150v2#page=9 "We show that for any discretization of the parameter space [0, 1], there exists an infinite family of distributions over MILP problem instances such that for any parameter in the discretization, the expected tree size is exponential in n."))
- **c6** Experimental setup: the variable selection rule of CPLEX 12.8.0.0 is overridden via a branch callback that enumerates all parameter values giving distinct trees; CPLEX cuts, primal heuristics and root-node preprocessing are disabled and node selection is best bound; the measure is average B&B tree size.([Experiments, p.17](https://arxiv.org/pdf/1803.10150v2#page=17 "We use the C API of IBM ILOG CPLEX 12.8.0.0 to override the default variable selection rule using a branch callback."))
- **c7** Empirical finding: across synthetic distributions (combinatorial auctions from CATS, facility location, clustering, agnostic linear separators) the relationship between the linear scoring rule's parameter and average tree size varies greatly by application, so the authors conclude parameters should be tuned per application and no value is universally effective.([Experiments, p.19](https://arxiv.org/pdf/1803.10150v2#page=19 "This implies that the parameters should be tuned on a per-application basis, and that no parameter value is universally effective."))
