## 主張

- **c1** Diagnosis: on 2-D normally distributed data, the standard Isolation Forest score map shows rectangular regions of lower anomaly score along the x and y directions compared with points at the same radial distance; the authors attribute these differences to the algorithm and note that two points of similar importance can then be categorized differently depending on the threshold.([Section 2 (Motivation), p.2](https://arxiv.org/pdf/1811.02141v3#page=2 "As we will see in later sections, the diﬀerence in the anomaly score in the x and y directions are indeed an artifacts introduced by the algorithm."))
- **c2** With two Gaussian clusters, the artifact is amplified where the bands intersect, producing low-score "ghost" clusters near (0, 0) and (10, 10); an anomaly near the origin would most likely be categorized as nominal. The authors state this increases the chances of false positives and indicates a non-existent structure.([Section 2 (Motivation), p.3](https://arxiv.org/pdf/1811.02141v3#page=3 "Not only does this increase the chances of false positives, it also wrongly indicates a non-existent structure in the data."))
- **c3** Mechanism: because each cut picks one random feature and a random value, all branch cuts are parallel to the coordinate axes; cuts still concentrate where the data are, but regions with few data points end up with many cuts through them, so e.g. a point near (4, 0) receives many more branching operations than one near (3, 3) although both are anomalies relative to the center.([Section 3 (Generalization of Isolation Forest), p.4](https://arxiv.org/pdf/1811.02141v3#page=4 "However, because of the constraint that the branch cuts are only vertical and horizontal, regions that don’t necessarily contain many data points end up with many branch cuts through them."))
- **c4** Rotating each tree's sub-sample by a random angle averages the bias out across trees and improves the score maps, but the authors call it not the ideal fix: each tree still has the rectangular bias, every tree must store its rotation, rotation is not obvious beyond 2-D and the approach can become cumbersome for large, high-dimensional data. They suggest EIF should be preferred over rotation.([Rotated Trees, p.5](https://arxiv.org/pdf/1811.02141v3#page=5 "In a sense the problem is not resolved, but only averaged out."))
- **c5** EIF branch cuts: a random slope is chosen by drawing each component of the normal vector from N(0, 1), which gives a uniform selection on the N-sphere; the intercept is drawn uniformly over the range of values at the branching point, and a point goes left if (x - p) . n <= 0. Intercepts still accumulate where the data are, but no region artificially receives more cuts.([Extended Isolation Forest, p.6](https://arxiv.org/pdf/1811.02141v3#page=6 "This results in a uniform selection of points on the N-sphere."))
- **c6** Extension levels: setting coordinates of the normal vector to zero gives levels Ex 0 to Ex N-1; Ex 0 is identical to the standard Isolation Forest. The authors suggest lower extension levels may be useful when the dynamic ranges of dimensions differ strongly, and that for data essentially distributed along a line the standard Isolation Forest would probably give the best result.([High Dimensional Data and Extension Levels, p.7](https://arxiv.org/pdf/1811.02141v3#page=7 "Isolation Forest method would probably yield the most optimal result."))
- **c7** AUC protocol: on the synthetic examples both algorithms are trained on 2000 points and then 200 anomalous points are added and scored; AUROC and AUPRC are also reported on five real benchmark datasets (Cardio, ForestCover, Ionosphere, Mammography, Satellite). The only comparison is EIF vs the standard Isolation Forest; no number of trees, sub-sample size, train/test split or number of repeats for the benchmark runs was found in the text (searched for sub-sample, trees, split, repeat, runs, contamination).([Section 4 (AUC Comparison), p.10](https://arxiv.org/pdf/1811.02141v3#page=10 "In order to obtain the AUC values for the example datasets, we ﬁrst train both algorithms on 2000 data points in each case distributed as seen previously."))
- **c8** On the real benchmarks the authors report improved AUC for EIF but note the improvement may seem modest in some cases and appreciable in others, because the axis-parallel limitation affects some datasets more than others.([Section 4 (AUC Comparison), p.10](https://arxiv.org/pdf/1811.02141v3#page=10 "Naturally, the axis-parallel limitation has more eﬀects on some datasets than other."))
- **c9** Cost: in convergence plots of the score versus forest size (2-D, 3-D and 4-D blobs), the scores settle quickly and the authors find no appreciable difference in convergence rate between the standard Isolation Forest and EIF at any extension level, concluding that the number of trees should be the same and that EIF does not sacrifice computational efficiency. No wall-clock timing table was found in the body (the abstract's statement on computation time is supported by the convergence plots).([Convergence of Anomaly Scores, p.11](https://arxiv.org/pdf/1811.02141v3#page=11 "Moreover we ﬁnd no appreciable diﬀerence between the standard Isolation Forest and the Extended Isolation Forest, including all the extension levels."))
