## 主張

出典のリンクは原論文PDFの該当ページを開く。リンクにカーソルを合わせると原文の引用が表示される。

- **c1** Differentiable oblivious trees: instead of REINFORCE or Gumbel-softmax, which the authors say typically require long training time, NODE uses alpha-entmax to learn sparse splitting-feature choices that depend on only a few features, and a scaled two-class entmax to relax the threshold comparison; the relaxation equals a classic oblivious tree when both reach one-hot states.([Section 3.1, p.4](https://arxiv.org/pdf/1909.06312v2#page=4 "Instead, we propose to use the α-entmax transformation (Peters et al., 2019) as it is able to learn sparse choices, depending only on a few features, via standard gradient descent."))
- **c2** Deep architecture: a sequence of k NODE layers, each taking the concatenation of all previous layers (including the input features) as input, following DenseNet; the final prediction is a simple average of all trees from all layers, and tree outputs can have dimension l > number of classes so that early layers produce features for later ones.([Section 3.2, p.5](https://arxiv.org/pdf/1909.06312v2#page=5 "Similar to DenseNet, our architecture is a sequence of k NODE layers (see Section 3.1), where each layer uses a concatenation of all previous layers as its input."))
- **c3** Training protocol: each feature is quantile-transformed to a normal distribution (observed to be important for stable training and faster convergence), data-aware initialization is used, training uses Quasi-Hyperbolic Adam with parameters from the original paper, parameters are averaged over 5 consecutive checkpoints, and the stopping point is chosen on a hold-out validation set.([Section 3.3, p.5](https://arxiv.org/pdf/1909.06312v2#page=5 "In experiments, we observed that this step was important for stable training and faster convergence."))
- **c4** Evaluation protocol: six open-source datasets (Epsilon, YearPrediction, Higgs, Microsoft, Yahoo, Click) with provided train/test splits and 20% of the train set as validation, fixed splits for all methods (the appendix says Yahoo uses the split provided by its authors); baselines are CatBoost, XGBoost and a fully connected network (FCNN); mean and standard deviation over ten runs with different random seeds are reported. Ranking datasets are treated as regression with MSE.([Section 4.1, p.6](https://arxiv.org/pdf/1909.06312v2#page=6 "For all methods, we report mean performance and standard deviations computed over ten runs with different random seeds."))
- **c5** Tuning budget: CatBoost, XGBoost and FCNN are tuned with 50 steps of TPE (Hyperopt), with the number of trees (max 2048) set on validation at each step; NODE is tuned by grid search over number of layers {2, 4, 8}, total tree count {1024, 2048} and tree output dimension {2, 3} with learning rate fixed at 1e-3, so the budgets differ in form between NODE and the baselines.([Appendix (Optimization of hyperparameters), p.11](https://arxiv.org/pdf/1909.06312v2#page=11 "For each method, we perform 50 steps of Tree-structured Parzen Estimator (TPE) optimization algorithm."))
- **c6** Default-hyperparameter regime: GBDTs use package defaults with only the number of trees (up to 2048) set on validation, NODE uses a single layer of 2048 trees of depth six (inherited from CatBoost defaults), and FCNN is not compared because it typically requires much tuning and no setting suitable for all datasets was found.([Section 4.1, p.6](https://arxiv.org/pdf/1909.06312v2#page=6 "We do not compare with FCNN in this regime, as it typically requires much tuning, and we did not ﬁnd the set of parameters, appropriate for all datasets."))
- **c7** Relation to GBDTs within the paper: with default hyperparameters NODE is reported to outperform CatBoost and XGBoost on all six datasets; with tuned hyperparameters it outperforms them on most tasks, the exceptions being Yahoo and Microsoft where tuned XGBoost is best, which the authors speculate means oblivious trees are an inappropriate inductive bias for Yahoo.([Section 4.1, p.7](https://arxiv.org/pdf/1909.06312v2#page=7 "Given the large advantage of XGBoost over CatBoost on Yahoo, we speculate that the usage of oblivious decision trees is an inappropriate inductive bias for this dataset."))
- **c8** Critique of prior work: the authors state that earlier tabular DNN architectures mostly did not compare with properly tuned GBDT implementations, and that a preprint reporting marginal gains over default-parameter GBDT faced much stronger baselines in their experiments.([Section 2, p.3](https://arxiv.org/pdf/1909.06312v2#page=3 "The recent preprint (Ke et al., 2018) reports the marginal improvement over GBDT with default parameters, but in our experiments, the baseline performance is much higher."))
- **c9** Ablation of choice functions (YearPrediction and Epsilon): entmax with alpha = 1.5 is reported to outperform softmax, sparsemax and Gumbel-softmax across the experiments; sparsemax and softmax are not universal (each wins on one dataset), and Gumbel-softmax could not learn deep architectures, probably because its stochasticity makes early-layer responses too noisy.([Section 4.2, p.8](https://arxiv.org/pdf/1909.06312v2#page=8 "Another observation is that Gumbel-Softmax is unable to learn deep architectures with both constant and annealed temperature schedules."))
- **c10** Oblivious decision tree (Eq. 1): a depth-d ODT with splitting features f_1..f_d and thresholds b_1..b_d outputs h(x) = R[1(f_1(x) - b_1), ..., 1(f_d(x) - b_d)], where 1 is the Heaviside function and R is a table of 2^d responses indexed by the binary comparison results.([Section 3.1, p.3](https://arxiv.org/pdf/1909.06312v2#page=3 "In this notation, the tree output is deﬁned as:"))
- **c11** Differentiable relaxation (Eq. 2): the feature choice becomes a weighted sum fhat_i(x) = sum_j x_j entmax_alpha(F_ij) with weights from entmax over a learnable feature-selection matrix F, and the Heaviside comparison becomes c_i(x) = sigma_alpha((f_i(x) - b_i)/tau_i), with sigma_alpha(x) = entmax_alpha([x, 0]) a two-class entmax and learnable thresholds b_i and scales tau_i.([Section 3.1, p.4](https://arxiv.org/pdf/1909.06312v2#page=4 "with weights computed as entmax over the learnable feature selection matrix"))
