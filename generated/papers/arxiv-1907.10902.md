## 主張

出典のリンクは原論文PDFの該当ページを開く。リンクにカーソルを合わせると原文の引用が表示される。

- **c1** Define-by-run: borrowing the term from deep-learning frameworks, Optuna lets the user construct the search space dynamically during the objective's execution (via trial suggest calls, with ordinary loops and conditionals), instead of defining the whole space in advance.([Define-by-run API, p.2](https://arxiv.org/pdf/1907.10902v1#page=2 "Following the original deﬁnition, we use the term deﬁne-by-run in the context of optimization framework to refer to a design that allows the user to dynamically construct the search space."))
- **c2** The authors claim that all previous hyperparameter optimization frameworks require the user to construct the search space statically for each model, which they argue is extremely hard for large experiments with many model types and conditional variables.([Introduction, p.1](https://arxiv.org/pdf/1907.10902v1#page=1 "Firstly, all previous hyperparameter optimization frameworks to date require the user to statically construct the parameter-search"))
- **c3** Sampling: Optuna supports independent sampling (e.g. TPE) and relational sampling (e.g. CMA-ES, GP-BO), identifying concurrence relations among parameters after some independent samplings; the authors note that independent sampling is not necessarily naive and that cost-effectiveness depends on environment and task. No statement that TPE is the default sampler was found in the text (searched for default).([Efficient Sampling and Pruning Mechanism, p.4](https://arxiv.org/pdf/1907.10902v1#page=4 "The independent sampling is not necessarily a naive option, because some sampling algorithms like TPE [6] are known to perform well even without using the parameter correlations, and the cost eﬀectiveness for both relational and independent sampling depends on environment and task."))
- **c4** Pruning: intermediate values are reported via report and checked via should_prune; the pruner is a variant of Asynchronous Successive Halving that promotes trials within the top 1/eta of their rung; to avoid storing many checkpointed configurations the implementation does not allow repechage.([Efficient Sampling and Pruning Mechanism, p.5](https://arxiv.org/pdf/1907.10902v1#page=5 "our implementation does not allow repechage"))
- **c5** Sampler benchmark protocol: on a collection of 56 black-box optimization test cases, TPE+CMA-ES (TPE for the first 40 steps, CMA-ES afterwards) is compared with random search, Hyperopt, SMAC3 and GPyOpt using the best value found in 80 trials, 30 repetitions per study and a paired Mann-Whitney U test with alpha = 0.0005, following Dewancker et al.([Experimental Evaluation, p.6](https://arxiv.org/pdf/1907.10902v1#page=6 "For TPE+CMA-ES, we used TPE for the ﬁrst 40 steps and used CMA-ES for the rest."))
- **c6** In that benchmark the GP-based GPyOpt performed better than TPE+CMA-ES in 34 of 56 cases, while TPE+CMA-ES took an order of magnitude less time per trial; the authors suggest the user may use a GP-based method if the time of evaluation is a bottleneck.([Experimental Evaluation, p.6](https://arxiv.org/pdf/1907.10902v1#page=6 "Meanwhile, GPyOpt performed better than TPE+CMA-ES in 34/56 cases in terms of the best-attained loss value."))
- **c7** Pruning evaluation protocol: simplified AlexNet (8 hyperparameters) on SVHN, each study on one Tesla P100 GPU stopped after 4 hours and repeated 40 times; the reported curves are average test errors. Whether the optimized objective was a validation or test error was not found stated for this experiment (searched for validation).([Section 5.2 (Performance Evaluation of Pruning), p.7](https://arxiv.org/pdf/1907.10902v1#page=7 "We repeated each study 40 times."))
- **c8** The authors report that their ASHA implementation significantly outperforms median pruning (featured in Vizier) and conclude that a sampling algorithm alone is not sufficient for cost-effective optimization, because per-trial computational cost is the bottleneck.([Section 5.2 (Performance Evaluation of Pruning), p.7](https://arxiv.org/pdf/1907.10902v1#page=7 "This result also suggests that sampling algorithm alone is not suﬃcient for cost-eﬀective optimization."))
- **c9** Distributed optimization with TPE on 1, 2, 4 and 8 workers: the authors note that for sequential model-based methods such as TPE the number of workers need not translate into efficiency, but observe that scores per number of trials barely change with the number of workers, i.e. performance scales linearly with workers (also with ASHA pruning).([Performance Evaluation of Distributed Optimization, p.7](https://arxiv.org/pdf/1907.10902v1#page=7 "Note that the optimization scores per the number of trials (i.e., parallelization eﬃciency) barely changes with the number of workers."))
