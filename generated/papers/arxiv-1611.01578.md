## 主張

出典のリンクは原論文PDFの該当ページを開く。リンクにカーソルを合わせると原文の引用が表示される。

- **c1** Method: a recurrent controller generates a string describing a child network; the child is trained on the real data, its validation-set accuracy is used as the reward, and the policy gradient of this reward updates the controller so that it assigns higher probability to architectures that receive high accuracies.([Introduction, p.2](https://arxiv.org/pdf/1611.01578v2#page=2 "Using this accuracy as the reward signal, we can compute the policy gradient to update the controller."))
- **c2** Training: because the reward R (validation accuracy of the trained child) is non-differentiable, the controller parameters are updated with the REINFORCE rule (citing Williams, 1992), averaged over m sampled architectures per batch; to reduce the high variance of this unbiased estimate, a baseline is subtracted, which is an exponential moving average of the previous architecture accuracies.([Section 3.2, p.4](https://arxiv.org/pdf/1611.01578v2#page=4 "In this work, our baseline b is an exponential moving average of the previous architecture accuracies."))
- **c3** Motivation relative to hyperparameter optimization (citing Bergstra et al., Snoek et al. and others): these methods only search fixed-length spaces, making it difficult to generate a variable-length configuration specifying network structure and connectivity, and in practice they often work better when supplied with a good initial model; Bayesian optimization methods that search non-fixed-length architectures exist but are described as less general and less flexible than the proposed method.([Related Work, p.2](https://arxiv.org/pdf/1611.01578v2#page=2 "Despite their success, these methods are still limited in that they only search models from a ﬁxed-length space."))
- **c4** Compute for the CIFAR-10 search: parameter-server shards S = 20, controller replicas K = 100 and child replicas m = 8, so 800 networks are trained on 800 GPUs concurrently at any time; each sampled child is trained for 50 epochs and the reward is the maximum validation accuracy of the last 5 epochs cubed, with 5,000 training examples held out as the validation set.([Section 4.1, p.7](https://arxiv.org/pdf/1611.01578v2#page=7 "which means there are 800 networks being trained on 800 GPUs concurrently at any time."))
- **c5** Selection protocol on CIFAR-10: after the controller trains 12,800 architectures, the architecture with the best validation accuracy is taken, a small grid search over learning rate, weight decay, batchnorm epsilon and the learning-rate decay epoch is run, and the best model from this grid search is run until convergence before computing test accuracy; the paper states that test performance is computed only once for the network that achieves the best result on the held-out validation set.([Section 4.1, p.7](https://arxiv.org/pdf/1611.01578v2#page=7 "After the controller trains 12,800 architectures, we ﬁnd the architecture that achieves the best validation accuracy."))
- **c6** Comparison caveats in the CIFAR-10 results: the best reported NAS error is obtained after adding 40 more filters to each layer of the searched architecture (in a setting where the controller predicts 13 layers, each a fully connected block of 3 layers, with pooling layers inserted at fixed positions); the authors note the DenseNet model with a lower error uses 1x1 convolutions to reduce parameters, which they did not do, so it is not an exact comparison.([Section 4.1, p.8](https://arxiv.org/pdf/1611.01578v2#page=8 "uses 1x1 convolutions to reduce its total number of parameters, which we did not do, so it is not an exact comparison."))
- **c7** Recurrent-cell search space on Penn Treebank: with base number 8, the search space has approximately 6 x 10^16 architectures, much larger than the 15,000 architectures the controller is allowed to evaluate; this search used S = 20, K = 400 and m = 1, i.e. 400 networks trained on 400 CPUs concurrently, with each child trained for 35 epochs.([Section 4.2, p.8](https://arxiv.org/pdf/1611.01578v2#page=8 "which is much larger than 15,000, the number of architectures that we allow our controller to evaluate."))
- **c8** Control experiment against random search (motivated, citing Bergstra & Bengio, 2012, by random search often being very hard to surpass): the authors state that both the best model and the average of the top models found with policy gradient are better than those found by random search; the comparison is reported only as perplexity improvements over iterations in a figure.([Section 4.2, p.10](https://arxiv.org/pdf/1611.01578v2#page=10 "The results show that not only the best model using policy gradient is better than the best model using random search, but also the average of top models is also much better."))
- **c9** REINFORCE gradient with baseline: the controller gradient is estimated as (1/m) sum_{k=1}^{m} sum_{t=1}^{T} grad_theta_c log P(a_t | a_(t-1):1; theta_c) (R_k - b), over m sampled architectures with T controller actions each, where R_k is the validation accuracy of the k-th child; subtracting a baseline b that does not depend on the current action keeps the estimate unbiased while reducing its variance.([Section 3.2, p.4](https://arxiv.org/pdf/1611.01578v2#page=4 "As long as the baseline function b does not depend on the on the current action, then this is still an unbiased gradient estimate."))
