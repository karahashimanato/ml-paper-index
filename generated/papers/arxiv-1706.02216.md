## 主張

出典のリンクは原論文PDFの該当ページを開く。リンクにカーソルを合わせると原文の引用が表示される。

- **c1** Motivation: most existing node-embedding approaches require all nodes to be present during training and are inherently transductive, so they do not naturally generalize to unseen nodes; GraphSAGE instead learns a function that generates embeddings by sampling and aggregating features from a node's local neighborhood.([Abstract, p.1](https://arxiv.org/pdf/1706.02216v4#page=1 "However, most existing approaches require that all nodes in the graph are present during training of the embeddings; these previous approaches are inherently transductive and do not naturally generalize to unseen nodes."))
- **c2** Forward propagation (Algorithm 1): at each of K depths every node aggregates the previous-depth representations of its neighbors into one vector, concatenates it with its own previous representation, feeds the result through a fully connected layer with nonlinearity, and the representations are normalized; as the process iterates nodes gain information from further reaches of the graph. In the minibatch setting the required neighborhood sets are first sampled up to depth K.([Section 3.1, p.4](https://arxiv.org/pdf/1706.02216v4#page=4 "The intuition behind Algorithm 1 is that at each iteration, or search depth, nodes aggregate information from their local neighbors, and as this process iterates, nodes incrementally gain more and more information from further reaches of the graph."))
- **c3** Relation to the WL test: with K = |V|, identity weight matrices and an appropriate hash function as aggregator (no non-linearity), Algorithm 1 is an instance of the Weisfeiler-Lehman isomorphism test ('naive vertex refinement'), which is known to fail in some cases; GraphSAGE replaces the hash with trainable aggregators, and the authors note that it is used to generate representations, not to test isomorphism.([Section 3.1, p.4](https://arxiv.org/pdf/1706.02216v4#page=4 "GraphSAGE is a continuous approximation to the WL test, where we replace the hash function with trainable neural network aggregators."))
- **c4** Neighbor sampling: N(v) is a fixed-size uniform draw from v's neighbors, redrawn at each depth k, so that per-batch space and time are fixed at O(prod_{i=1..K} S_i); without sampling, memory and runtime per batch are unpredictable and O(|V|) in the worst case. The authors found K = 2 with S1 * S2 <= 500 could achieve high performance, and list non-uniform samplers as future work.([Section 3.1, p.5](https://arxiv.org/pdf/1706.02216v4#page=5 "Without this sampling the memory and expected runtime of a single batch is unpredictable and in the worst case O(/V/)."))
- **c5** Mean / convolutional aggregator: the elementwise mean of neighbor vectors is nearly equivalent to the transductive GCN propagation rule; replacing lines 4-5 of Algorithm 1 by h_v^k = sigma(W * MEAN({h_v^(k-1)} union {h_u^(k-1)})) gives an inductive GCN variant (differing from Kipf et al.'s equation by a minor normalization constant). This 'convolutional' variant does not perform the concatenation step, which the authors view as a simple skip connection that leads to significant performance gains.([Section 3.3, p.5](https://arxiv.org/pdf/1706.02216v4#page=5 "The mean aggregator is nearly equivalent to the convolutional propagation rule used in the transductive GCN framework [17]."))
- **c6** Pooling aggregator: each neighbor's vector is passed independently through a fully connected layer and an elementwise max is taken across the neighbor set (single-layer MLP in this work); the authors report no significant difference between max- and mean-pooling in development tests and used max-pooling thereafter.([Section 3.3, p.6](https://arxiv.org/pdf/1706.02216v4#page=6 "The ﬁnal aggregator we examine is both symmetric and trainable."))
- **c7** Evaluation protocol: all predictions are on nodes unseen during training (and on entirely unseen graphs for PPI); citation data are split by time (train 2000-2004, test 2005) and Reddit by day (first 20 days train); all GraphSAGE variants share minibatch iterators, loss and sampler and sweep the same hyperparameter set chosen per variant on a validation set; the candidate hyperparameter values were determined on early validation tests using subsets of the citation and Reddit data that were then discarded.([Section 4, p.6](https://arxiv.org/pdf/1706.02216v4#page=6 "The set of possible hyperparameter values was determined on early validation tests using subsets of the citation and Reddit data that we then discarded from our analyses."))
- **c8** Depth and sampling sensitivity: setting K = 2 gave a consistent accuracy boost of around 10-15% on average over K = 1, while K beyond 2 gave marginal returns (0-5%) at a 10-100x runtime increase; returns diminished for larger sampled neighborhoods. DeepWalk was 100-500x slower at test time because new random walks and SGD rounds are needed to embed unseen nodes.([Section 4.3, p.8](https://arxiv.org/pdf/1706.02216v4#page=8 "However, the need to sample new random walks and run new rounds of SGD to embed unseen nodes makes DeepWalk 100-500× slower at test time."))
- **c9** Theorem 1 (assumptions stated): if node features lie in a compact subset of R^d and every pair of nodes has features at distance greater than a fixed C > 0, there exists a parameter setting of Algorithm 1 that approximates every node's clustering coefficient to arbitrary precision after K = 4 iterations (with a sufficiently high-dimensional model); the proof relies on properties of the pooling aggregator.([Section 5, p.9](https://arxiv.org/pdf/1706.02216v4#page=9 "Theorem 1 states that for any graph there exists a parameter setting for Algorithm 1 such that it can approximate clustering coefﬁcients in that graph to an arbitrary precision, if the features for every node are distinct (and if the model is sufﬁciently high-dimensional)."))
