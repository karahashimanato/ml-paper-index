## 主張

- **c1** Contrary to the common belief that SBC-type checks can never detect, for example, a program that samples from the prior and ignores the data, the authors show that test quantities depending on data make it possible to detect any conceivable mismatch between generator and probabilistic program (in principle; cf. Theorem 6 with the impractical density-ratio test quantity).([Introduction, p.5](https://arxiv.org/pdf/2211.02383v3#page=5 "We show that using test quantities that depend on data makes it possible to detect any conceivable mismatch between the generator and the probabilistic program."))
- **c2** Theorem 7: a posterior that ignores (part of) the data passes SBC for test quantities that use only the retained part of the data; in particular, programs sampling from the prior pass SBC against all test quantities that do not depend on data.([Theoretical results, p.9](https://arxiv.org/pdf/2211.02383v3#page=9 "We generalize the result that probabilistic programs sampling from the prior distribution will pass SBC against all test quantities that do not depend on data."))
- **c3** SBC is not the same check as the data-averaged posterior (prior equals the data-averaged posterior), contrary to assumptions in some literature: Example 2 constructs posteriors that satisfy the data-averaged-posterior condition but fail SBC, and others that pass SBC but violate it. The authors suspect the extra practical benefit of also checking the data-averaged posterior is small.([Theoretical results, p.10](https://arxiv.org/pdf/2211.02383v3#page=10 "We show that this is incorrect: Example 2 not only explicitly constructs posterior distributions that will satisfy (1) for some test quantity while not passing SBC, but also posterior distributions that pass SBC while not satisfying (1)."))
- **c4** SBC failure indicates that at least one of the generator, probabilistic program, and posterior approximation algorithm (including tuning parameters) is mismatched to the others, but SBC by itself cannot determine where the problem lies.([Practical considerations, p.4](https://arxiv.org/pdf/2211.02383v3#page=4 "However, by itself, SBC cannot determine where exactly the problem lies."))
- **c5** SBC, as a simulation method, cannot inform about a discrepancy between the process that generated the real data and the model's assumptions; for reliable inference it must be combined with other workflow elements that detect misspecification, such as posterior predictive checks or residual analysis.([Practical considerations, p.4](https://arxiv.org/pdf/2211.02383v3#page=4 "Additionally, SBC as a simulation method has no way to inform us about a discrepancy between the process that generated real data and the assumptions of our statistical model."))
- **c6** Precision limits in the multivariate normal case studies: if only a small part of the data is ignored, the joint likelihood turns detection into a problem of precision; missing a single data point in a large dataset (e.g. an off-by-one error) may change the posterior only slightly and be undetectable with realistic computational effort. The authors say adding the joint log-likelihood 'seems to be' a useful default.([Numerical case studies, p.13](https://arxiv.org/pdf/2211.02383v3#page=13 "Missing just a single datapoint in a large dataset (e.g., an off-by-one error in the probabilistic program) may change the posterior only slightly and be undetectable with realistic computational effort."))
- **c7** In the real-world ordered-simplex case study (an off-by-one error in a Jacobian), the log likelihood did not reveal the error quickly, showing it is not a panacea, especially when the problem lies with the prior; the log prior density seemed potentially useful there. The authors also describe SBC as useful for testing model components in isolation, akin to unit tests.([Real-world case study (Remarks), p.20](https://arxiv.org/pdf/2211.02383v3#page=20 "In this example, the log likelihood did not reveal the error quickly, showing that it is not a panacea, especially in cases where the problem lies with the prior."))
- **c8** Recommended default: use the individual model parameters as test quantities as well as the joint likelihood of the data and potentially a small number of other quantities (e.g. quantities tied to inferential goals, log prior, or pairwise products/differences when correlations matter). In all their simulated cases the joint likelihood detected the discrepancies, though for specific problems other quantities were more sensitive.([Conclusions, p.21](https://arxiv.org/pdf/2211.02383v3#page=21 "For practical use of SBC in everyday model and algorithm development, we recommend to use by default the individual model parameters as test quantities as well as the joint likelihood of the data and potentially a small number of other quantities."))
- **c9** Limitations: for nontrivial models a finite set of test quantities cannot guard against all ways an incorrect posterior can satisfy the SBC identity (though counterexamples become contrived as more are checked), and adding test quantities raises false failures without multiple-comparison correction or lowers power with it.([Limitations, p.21](https://arxiv.org/pdf/2211.02383v3#page=21 "For nontrivial models, adding a finite number of test quantities cannot guard against all possible ways the SBC identity may be satisfied by an incorrect posterior."))
