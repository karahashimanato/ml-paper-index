## 主張

出典のリンクは原論文PDFの該当ページを開く。リンクにカーソルを合わせると原文の引用が表示される。

- **c1** Data set and annotation: 37 real series (33 univariate, 4 multivariate) from sources such as WorldBank, EuroStat and Wikipedia, plus 5 simulated quality-control series added without the annotators' knowledge (42 in total). Annotators were data scientists and machine learning researchers deliberately chosen without domain background; the tool assigned series randomly, and each series was annotated by five of the eight annotators.([Section 4 (Annotation Collection), p.8](https://arxiv.org/pdf/2003.06222v3#page=8 "In total, eight annotators provided annotations for the 42 time series, with ﬁve annotators assigned to each time series."))
- **c2** Metrics: the covering metric (Jaccard-based, averaged over annotators) is used as the clustering metric (Hausdorff is disregarded because it can obscure methods with many false positives); the F1-score treats detections within a margin M of an annotation as true positives without double counting, with precision against the combined set of annotations and recall averaged over annotators. t = 1 is added as a trivial change point to keep precision and recall defined; M = 5 in the experiments.([Section 3, p.6](https://arxiv.org/pdf/2003.06222v3#page=6 "In the experiments we use a margin of error of M = 5."))
- **c3** Annotator consistency: in one-vs-rest evaluation the median annotator score was approximately 0.8 (covering) and 0.9 (F1); F1 values are generally higher because of the margin of error and because precision uses the union of annotations. The few low-agreement cases are often due to one or two annotators disagreeing with the others.([Section 4.4, p.9](https://arxiv.org/pdf/2003.06222v3#page=9 "The ﬁgures show that on average there is a high degree of agreement between annotators, with the median annotator score approximately 0.8 for the covering metric and 0.9 for the F1-score"))
- **c4** Protocol: two evaluations. Default uses each method's default settings from the package documentation (a data analyst without prior knowledge of parameter choices); Oracle reports the maximum score over a grid search of hyperparameters per series. The authors emphasize that Oracle is not necessarily a realistic measure because, in unsupervised CPD, users cannot in general tune parameters to match the unknown ground truth. Univariate and multivariate series are analysed separately, series are standardized, and computation time is not reported because implementation languages differ.([Section 5 (Experimental Setup), p.10](https://arxiv.org/pdf/2003.06222v3#page=10 "It should be emphasized that while the Oracle experiment is important from a theoretical point of view, it is not necessarily a realistic measure of practical algorithm performance."))
- **c5** Decision rule for Bayesian online methods: BOCPD-type algorithms following Adams and MacKay (2007) compute a full distribution over change point locations and do not return a single segmentation, so the maximum a posteriori (MAP) segmentation is used to compare them with the other methods.([Section 5 (Experimental Setup), p.11](https://arxiv.org/pdf/2003.06222v3#page=11 "To allow for comparisons to the other methods we use the maximum a posteriori (MAP) segmentation of the series (see, e.g., Fearnhead and Liu, 2007)."))
- **c6** bocpd settings: R package ocp with a Gaussian likelihood and its conjugate prior (described in the text as a 'negative inverse gamma prior'), prior mean 0 (data standardized), no run-length truncation. Default: intensity lambda_gap = 100, alpha0 = beta0 = kappa0 = 1. Grid: intensity in {10, 50, 100, 200} and alpha0, beta0, kappa0 each in {0.01, 0.1, 1, 10, 100}. bocpdms used the same settings but with run-length pruning to the best 100 run lengths during the grid search (for speed); rbocpdms used pruning and timeouts.([Appendix A, p.17](https://arxiv.org/pdf/2003.06222v3#page=17 "For the default experiment the intensity (λgap) was set to 100, the prior variables were set to α0 = 1, β0 = 1, and κ0 = 1."))
- **c7** Default setting: the zero baseline (always no change points) outperforms many methods, which the authors attribute partly to the small number of change points per series and say also suggests many methods return many false positives; no method performed significantly better than zero in the Default experiment, while this does not hold for Oracle.([Section 5, p.13](https://arxiv.org/pdf/2003.06222v3#page=13 "We also see that in our experiments no method performs signiﬁcantly better than the zero method on the Default experiment, while this does not hold for the Oracle experiment."))
- **c8** Oracle setting (rank analysis: Friedman test, pairwise Wilcoxon signed-rank tests with Holm correction, critical-difference diagrams): bocpd achieves the highest average rank, and the authors find it noteworthy that bocpd, with a simple Gaussian constant-mean segment model, outperforms methods allowing trend and seasonality (prophet) or autoregressive structure (bocpdms).([Section 5, p.13](https://arxiv.org/pdf/2003.06222v3#page=13 "It is noteworthy that even though bocpd assumes a simple Gaussian model with constant mean for each segment, it outperforms methods that allow for more complex time series behavior such as trend and seasonality (prophet), or autoregressive structures (bocpdms)."))
- **c9** Conclusion: with default parameters binseg performs best on univariate series but is not statistically significantly different from several other methods; with hyperparameter tuning bocpd outperforms all other methods on univariate and multivariate series, but its differences from some algorithms (binseg, segneigh and rfpop, among others) are not statistically significant. Future work could add automated hyperparameter tuning to bridge the Default-Oracle gap (perhaps inspired by Turner et al., 2009 for bocpd).([Section 6 (Discussion), p.14](https://arxiv.org/pdf/2003.06222v3#page=14 "However, the diﬀerences between it and some other algorithms (binseg, segneigh, and rfpop, among others) have been shown to not be statistically signiﬁcantly diﬀerent."))
