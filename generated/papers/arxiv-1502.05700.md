- **c1** Motivation: a major drawback of GP-based Bayesian optimization is that inference time grows cubically in the number of observations because a dense covariance matrix must be inverted; the authors argue this has made it infeasible to combine large-scale parallelism with GP-based BO as search spaces and required evaluations grow.([1. Introduction, p.1](https://arxiv.org/pdf/1502.05700v2#page=1 "inference time grows cubically in the number of observations"))
- **c2** DNGO surrogate: a Bayesian linear regressor is added to the last hidden layer of a deep neural network, marginalizing only the output weights while using a point estimate for the remaining parameters (a pragmatic alternative to fully Bayesian neural networks, which the authors describe as very computationally expensive at large scale).([3. Adaptive Basis Regression with Deep Neural Networks, p.3](https://arxiv.org/pdf/1502.05700v2#page=3 "we take a pragmatic approach and add a Bayesian linear regressor to the last hidden layer of a deep neural network"))
- **c3** Cost: the resulting adaptive basis regression scales linearly in the number of observations and cubically in the basis function dimensionality, which allows an explicit trade-off between evaluation time and model capacity; the matrix to invert grows with the output dimensionality D rather than the number of observations N.([3. Adaptive Basis Regression with Deep Neural Networks, p.3](https://arxiv.org/pdf/1502.05700v2#page=3 "scales linearly in the number of observations, and cubically in the basis function dimensionality"))
- **c4** Design choices matter: the activation function significantly altered BO performance; ReLU units can lead to very poor uncertainty estimates and excessive exploration, so bounded tanh units are used (a ReLU network with tanh only on the last layer is suggested if the smoothness assumption needs relaxing).([3.1.1. Network Architecture, p.4](https://arxiv.org/pdf/1502.05700v2#page=4 "the commonly used rectiﬁed linear (ReLU) function can lead to very poor estimates of uncertainty, which causes the Bayesian optimization routine to explore excessively"))
- **c5** The surrogate network's own hyperparameters (learning rate, momentum, layer sizes, l2 penalties, dropout) were tuned with GP-based BO (Spearmint) to minimize the average relative loss on a series of benchmark global optimization problems; the chosen architecture (3 hidden layers of about 50 units, no dropout) is used throughout the evaluation. The text does not state whether these tuning problems overlap the HPOLib problems used later for evaluation.([3.1.1. Network Architecture, p.4](https://arxiv.org/pdf/1502.05700v2#page=4 "In order to tune any remaining hyperparameters, such as the width of the hidden layers and the amount of regularization, we used GP-based Bayesian optimization."))
- **c6** Parallelism: following Snoek et al. (2012), pending experiments are handled by averaging EI over fantasy outcomes; with a GP the cost of EI per candidate becomes cubic in the size of the augmented dataset, restricting the number of running experiments and fantasy sets, whereas DNGO allows both to be scaled up.([3.3. Parallel Bayesian Optimization, p.6](https://arxiv.org/pdf/1502.05700v2#page=6 "With DNGO it is possible to scale both of these up to accommodate a much higher degree of parallelism."))
- **c7** HPOLib benchmark comparison: DNGO is compared with SMAC (random forests), TPE and the input-warped GP method of Snoek et al. (2014) (Spearmint) on continuous HPOLib problems, each method run 10 times; the authors report that DNGO significantly outperforms SMAC and TPE and is competitive with the GP approach in the number of evaluations needed.([4.1. HPOLib Benchmarks, p.6](https://arxiv.org/pdf/1502.05700v2#page=6 "DNGO signiﬁcantly outperforms SMAC and TPE, and is competitive with the Gaussian process approach"))
- **c8** Massively parallel use case (image caption generation with a log-bilinear model, 11 hyperparameters, average 26.6 hours per evaluation): validation BLEU was optimized with 300-800 experiments in parallel, about 2500 experiments in total; test-set results of the best models are compared with LSTM results reported in other papers.([4.2. Image Caption Generation, p.7](https://arxiv.org/pdf/1502.05700v2#page=7 "we proposed and evaluated approximately 2500 experiments—the equivalent of over 2700 CPU days—in less than one week"))
