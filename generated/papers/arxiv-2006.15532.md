## 主張

出典のリンクは原論文PDFの該当ページを開く。リンクにカーソルを合わせると原文の引用が表示される。

- **c1** Prior on changepoints: the run length of the i-th segment is exponential with its own rate q_i, i.e. a latent left-to-right Markov chain on a countably infinite state space; this lets the recurrence rate vary across segments (avoiding the potential bias of a constant rate) and lets the number of changepoints grow without a fixed or upper bound as data arrive.([Section 2, p.7](https://arxiv.org/pdf/2006.15532v1#page=7 "We assume the run length of the i-th segment is exponentially distributed with a rate parameter qi."))
- **c2** Motivation: when changepoints are detected event by event (e.g. Fearnhead 2006 recursions), both computational and memory cost are quadratic in the number of observations, which the author calls prohibitive for large N; pruning or particle filtering are often applied to cope.([Introduction, p.4](https://arxiv.org/pdf/2006.15532v1#page=4 "In this case, both the computational cost and memory cost are quadratic to the number of observations, which is prohibitive for large N."))
- **c3** Cost and exactness: FFBS on the uniform times has computational and memory cost quadratic in the number of uniform times K rather than in n. If the rate matrix Q is known, changepoints can be sampled exactly; otherwise FFBS is embedded in a two-block Gibbs sampler that samples approximately from the posterior, with conjugate Gamma(a, b) priors on q_i whose hyperparameters are often specified manually.([Section 3, p.11](https://arxiv.org/pdf/2006.15532v1#page=11 "Firstly, both the computational cost and the memory cost of this version of FFBS algorithm are only quadratic to the number of uniform times K, instead of the number of observations, which is otherwise prohibitive when the ﬁltering probabilities are computed and stored in an event-by-event scale."))
- **c4** Limitation of the basic sampler: with a constant uniformization rate the algorithm is suitable only when run lengths are nearly regular, because highly variable q_i make the Poisson rate dominated by the largest one and inflate cost; a piecewise-constant nonhomogeneous rate simulated by thinning is used instead.([Section 3, p.12](https://arxiv.org/pdf/2006.15532v1#page=12 "The algorithm is suitable only when the run lengths between consecutive changepoints are nearly regular."))
- **c5** Approximation and bias: consecutive closely spaced uniform times are often sampled as separate changepoints ('knots'); they are pruned by repeating the backward-sampling step and keeping the furthest location, which the author says will possibly lead to slightly biased changepoint location estimates, as a price for avoiding inflated memory and computation. A truncation bound on the number of Poisson events is also imposed.([Section 3, p.13](https://arxiv.org/pdf/2006.15532v1#page=13 "This straightforward approach to pruning knots among changepoints will possibly lead to slightly biased estimation of the locations of changepoints, see simulation studies in the following sections."))
- **c6** Tuning: the resolution parameter k (uniformization rate = k times q_i) trades accuracy for cost: large k gives finer time scale and more accurate estimates but quadratically inflated memory and computation, small k a coarser scale and lower accuracy, so it needs careful selection.([Section 3, p.15](https://arxiv.org/pdf/2006.15532v1#page=15 "The tuning parameter needs to be carefully selected for a tradeoﬀbetween the accuracies and eﬃciencies."))
- **c7** Simulation (1200 Gaussian observations, 10 mean changepoints, known variance and conjugate mean prior, 6000 Gibbs iterations keeping the last 3000; k = 5, 11, 15 compared): remaining knots make the posterior of the number of changepoints tend to overestimate it, so the author recommends counting bumps in the posterior location histogram instead, and reports that the MAP locations from the continuous-time Viterbi algorithm were closer to the truth than posterior means.([Simulation Studies, p.18](https://arxiv.org/pdf/2006.15532v1#page=18 "Generally, the posterior of the number of changepoints summarized from this scheme tends to overestimate the number of changepoints."))
- **c8** Robustness issue: in the sparse long-series simulation (n = 10000 exponential observations, 3 changepoints) the algorithm occasionally broke down at low resolution because all filtering probabilities underflow to zero; the author says pilot runs might be necessary to choose the resolution parameter.([Simulation Studies, p.20](https://arxiv.org/pdf/2006.15532v1#page=20 "It is noted that the algorithm occasionally break down at low resolution (small k), due to that all the ﬁltering probabilities drop to zeros exponentially fast, causing underﬂow problems, which is diﬃcult to deal with for the moment."))
- **c9** Real data: for New Zealand deep earthquakes (674 events, quarterly Poisson counts over 70 years, k = 15) large uncertainties appear in both the number and locations of changepoints; the MAP number is 2 but the author deduces at least two or three changepoints. Well-log data were analysed after manually removing outliers. No comparison with other changepoint methods was found in the paper.([Real Numerical Examples, p.21](https://arxiv.org/pdf/2006.15532v1#page=21 "From the ﬁgure, it is observed that large uncertainties appear for the number of changepoints and their locations."))
