## 主張

出典のリンクは原論文PDFの該当ページを開く。リンクにカーソルを合わせると原文の引用が表示される。

- **c1** Motivation: Bayesian uncertainty estimates often fail to capture the true data distribution (e.g. a 90% credible interval not containing the outcome 90% of the time); the authors attribute this to model bias, i.e. a predictor not being expressive enough. The abstract also cites model misspecification and approximate inference.([Section 1 (Introduction), p.1](https://arxiv.org/pdf/1807.00263v1#page=1 "This problem arises because of model bias: a predictor may not be sufﬁciently expressive to assign the right probability to every credible interval, just as it may not be able to always assign the right label to a datapoint."))
- **c2** Definition: a forecaster is calibrated if, over the dataset, the fraction of y_t below the predicted p-quantile converges to p for all p (sufficient condition under i.i.d. data: P(Y <= F_X^{-1}(p)) = p), which extends to any interval; related to Gneiting et al.'s probabilistic calibration.([Section 3.1 (Calibration), p.3](https://arxiv.org/pdf/1807.00263v1#page=3 "In other words, the empirical and the predicted CDFs should match as the dataset size goes to inﬁnity."))
- **c3** Calibration is not sufficient: the unconditional forecast F(y) = P(Y <= y) is calibrated but ignores the features; forecasts must also be sharp (small predictive variance).([Section 3.1 (Calibration and Sharpness), p.4](https://arxiv.org/pdf/1807.00263v1#page=4 "In order to be useful, forecasts must also be sharp."))
- **c4** Guarantee as stated: the procedure produces calibrated forecasts given enough i.i.d. data and applies to any regression model; the authors contrast this with existing methods (concrete dropout, deep ensembles) that require modifying the forecaster and may not be calibrated even with large data. No formal theorem or proof of this guarantee was found in the text (searched for theorem, proof, guarantee).([Section 3.2, p.4](https://arxiv.org/pdf/1807.00263v1#page=4 "This approach is simple, produces calibrated forecasts given enough i.i.d. data"))
- **c5** Protocol recommendation: as in classifier recalibration, R should be fit on a separate calibration set to reduce overfitting, or by K-fold training with hold-out folds as calibration sets and averaging the K models; isotonic regression is recommended because the target function is monotone and it is non-parametric.([Section 3.2, p.5](https://arxiv.org/pdf/1807.00263v1#page=5 "As in classiﬁer recalibration, it is advisable to ﬁt R on a separate calibration set in order to reduce overﬁtting."))
- **c6** Protocol actually used: in the experiments the recalibrator (isotonic regression) was fit on the same training set as the base model; the authors state they did not observe significant overfitting and did not use a distinct calibration set.([Section 4.1 (Setup), p.6](https://arxiv.org/pdf/1807.00263v1#page=6 "We didn’t observe signiﬁcant overﬁtting and did not use a distinct calibration set."))
- **c7** Evaluation setup: eight UCI datasets (194 to 8192 examples), 25% random test split, averages over 5 random splits; models: Bayesian ridge regression and MC-dropout feedforward/recurrent networks; baselines: concrete dropout and a deep ensemble of 5 heteroscedastic networks; calibration error with unit weights. Also Make3D depth estimation, grocery sales forecasting, and a model-based RL inventory task.([Section 4.1 (Setup), p.6](https://arxiv.org/pdf/1807.00263v1#page=6 "There is generally no standard train/test split, hence we randomly assign 25% of each dataset for testing, and use the rest for training."))
- **c8** Using only the distance from a point forecast as the feature yields calibrated forecasts even for a non-probabilistic regressor, but intervals then have the same width everywhere, making them less useful for identifying uncertain inputs; heteroscedastic features are suggested instead.([Section 3.4 (Features for Recalibration), p.5](https://arxiv.org/pdf/1807.00263v1#page=5 "However, conﬁdence intervals will have the same width everywhere independently of x (e.g. Figure 4, left); this makes them less useful at identifying points x where the model is uncertain."))
- **c9** Limitations: recalibration preserves the accuracy of point estimates; a recalibrated quantile only becomes worse with insufficient recalibration data or distribution shift, and forecasts may become less sharp if the original model underestimated its uncertainty.([Section 5 (Discussion), p.8](https://arxiv.org/pdf/1807.00263v1#page=8 "A recalibrated estimate of the median (or any other quantile) only becomes worse if there is insufﬁcient data for recalibration, or there is a shift in the data distribution."))
