## 主張

出典のリンクは原論文PDFの該当ページを開く。リンクにカーソルを合わせると原文の引用が表示される。

- **c1** Prior predictive checks use simulations from the model rather than observed data, so they refine the model without using the data multiple times; in their logistic regression example, independent priors on coefficients imply increasingly extreme predictions as the number of covariates grows, a general phenomenon in regression models.([Section 2.4 (Prior predictive checking), p.10](https://arxiv.org/pdf/2011.01808v1#page=10 "This is a general phenomenon in regression models where as the number of predictors increases, we need stronger priors on model coeﬃcients (or enough data) if we want to push the model away from extreme predictions."))
- **c2** Recommended standard practice is to run at least until R-hat is below 1.01 for all parameters and quantities of interest (citing Vehtari et al., 2020) and to also monitor the multivariate R* statistic; earlier stopping can make sense in early stages of modeling, since big issues (especially coding errors) often appear after a few iterations.([How long to run an iterative algorithm, p.13](https://arxiv.org/pdf/2011.01808v1#page=13 "There are times when earlier stopping can make sense in the early stages of modeling."))
- **c3** The first validation step is that fitting finishes in acceptable time with reasonable convergence diagnostics (for HMC: no divergent transitions, R-hat near 1, sufficient ESS for central tendency, tail quantiles and energy), but these diagnostics cannot protect against a program that is computed correctly but encodes a different model than intended; hence models are first fit to simulated data.([Using constructed data to find and understand problems, p.16](https://arxiv.org/pdf/2011.01808v1#page=16 "However, those diagnostics cannot protect against a probabilistic program that is computed correctly but encodes a diﬀerent model than the user intended."))
- **c4** Fake-data simulation: one cannot run a single fake-data simulation and declare that everything works, though a single run will often reveal blatant errors (e.g. catastrophic failure of parameter recovery from code fitting the wrong model).([Section 4.1 (Fake-data simulation), p.17](https://arxiv.org/pdf/2011.01808v1#page=17 "It is not possible to run a single fake data simulation, compute the associated posterior distribution, and declare that everything works well."))
- **c5** Good inference on fake data generated from the same model gives no guarantee of sensible inference on real data, but failure on such fake data makes reasonable inference on real data hopeless; fake-data simulations provide an upper bound on what can be learned about a latent process.([Section 4.1 (Fake-data simulation), p.18](https://arxiv.org/pdf/2011.01808v1#page=18 "Fake-data simulations provide an upper bound of what can be learned about a latent process."))
- **c6** SBC is in many ways superior to benchmarking against a single truth point but requires fitting the model many times, a substantial computational cost especially without extensive parallelization; the authors see SBC and truth-point benchmarking as two ends of a spectrum and state that understanding SBC with a small number of draws is an open research question.([Simulation-based calibration, p.18](https://arxiv.org/pdf/2011.01808v1#page=18 "While in many ways superior to benchmarking against a truth point, simulation-based calibration requires ﬁtting the model multiple times, which incurs a substantial computational cost, especially if we do not use extensive parallelization."))
- **c7** SBC clashes somewhat with modelers' tendency to specify priors wider than they believe necessary: weakly informative priors can occasionally produce extreme simulated datasets that make an algorithm that works on realistic data fail dramatically, which the authors describe as a problem with the prior rather than the computation.([Simulation-based calibration, p.18](https://arxiv.org/pdf/2011.01808v1#page=18 "A serious problem with SBC is that it clashes somewhat with most modelers’ tendency to specify their priors wider than they believe necessary."))
- **c8** Folk theorem of statistical computing (citing Yao, Vehtari, and Gelman, 2020): computational problems often indicate a problem with the model. Not always, since some models are legitimately hard to fit, but many cases of poor convergence correspond to parameter regions of no substantive interest or to a nonsensical model; the first instinct should not be more computation (more iterations, smaller HMC step size) but to check for a substantive pathology.([Section 5.1 (The folk theorem of statistical computing), p.22](https://arxiv.org/pdf/2011.01808v1#page=22 "When you have computational problems, often there’s a problem with your model (Yao, Vehtari, and Gelman, 2020)."))
- **c9** Stated holes in the workflow: in prior and posterior predictive checks a wrong model can pass silently by overfitting; in simulation-based calibration an incorrect computation program can satisfy the diagnostics if the posterior stays in the prior; the authors state all workflows have holes.([Section 12.6 (Going forward), p.67](https://arxiv.org/pdf/2011.01808v1#page=67 "In simulation based calibration, an incorrect computation program can satisfy the diagnostics if the posterior stays in the prior."))
