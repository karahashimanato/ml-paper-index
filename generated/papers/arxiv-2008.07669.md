## 主張

出典のリンクは原論文PDFの該当ページを開く。リンクにカーソルを合わせると原文の引用が表示される。

- **c1** Framework: the coefficient function c(t) = coef_t(proj_t(f)) of the optimal polynomial projection of the input history (with respect to a time-varying measure) has the form of an ODE d/dt c(t) = A(t)c(t) + B(t)f(t), so it can be obtained online by solving an ODE or, after discretization, by a recurrence that maps a sequence of reals to a sequence of N-dimensional vectors.([Section 2.2, p.4](https://arxiv.org/pdf/2008.07669v2#page=4 "Thus our results show how to tractably obtain c(t) online by solving an ODE, or more concretely by running a discrete recurrence."))
- **c2** Sliding-window measures: the translated Legendre (LegT, uniform weight on [t - theta, t], window-length hyperparameter theta) and translated Laguerre (LagT, exponentially decaying) measures give LTI ODEs; the LegT case reproduces the LMU update. The derivation shows an additional approximation outside the projection: the sliding-window update needs f(t - theta), which is no longer available, and instead assumes the current coefficients model the function well enough to recover it.([Section 2.3, p.5](https://arxiv.org/pdf/2008.07669v2#page=5 "Equation (1) proves the LMU update [71, equation (1)]."))
- **c3** Discretization: the continuous-time ODE is turned into a discrete recurrence with a step size Delta t (Euler is used for illustration; the experiments use the bilinear and ZOH methods), and this process is in general sensitive to the step size hyperparameter; differences between timestamps can serve as an adaptive step size for timestamped data with missing values.([Section 2.4, p.5](https://arxiv.org/pdf/2008.07669v2#page=5 "In general, this process is sensitive to the discretization step size hyperparameter ∆t."))
- **c4** HiPPO-LegS uses the scaled Legendre measure mu(t) = (1/t) I[0,t] (uniform weight on all history) and is timescale-equivariant (Proposition 3): dilating the input does not change the coefficients, which the authors reflect informally as LegS having no timescale hyperparameters, whereas LegT has a window length theta and LegT/LagT have a step size hyperparameter in discrete time.([Section 3, p.6](https://arxiv.org/pdf/2008.07669v2#page=6 "Formally, the HiPPO-LegS operator is timescale-equivariant: dilating the input f does not change the approximation coeﬃcients."))
- **c5** Theoretical properties of LegS: under any generalized bilinear transform discretization one recurrence step costs O(N) operations (generically O(N^2) for multiplication by the state matrix); the gradient norm of the output at t1 with respect to the input at t0 is Theta(1/t1) (Proposition 5); and the approximation error is O(tL/sqrt(N)) for L-Lipschitz inputs (Proposition 6).([Section 3, p.6](https://arxiv.org/pdf/2008.07669v2#page=6 "Under any generalized bilinear transform discretization (cf. Appendix B.3), each step of the HiPPO-LegS recurrence in equation (4) can be computed in O(N) operations."))
- **c6** pMNIST protocol and result as stated in the text: HiPPO variants are an MGU with an extra hippo layer, the memory size N is tied to the hidden dimension so methods have comparable hidden units and parameters, a Rand baseline (random A and B) checks that the derived dynamics matter, and LegT is run with ideal and mis-specified theta. The authors state a test accuracy of 98.3% for HiPPO-LegS; the comparison with non-recurrent models uses reported results from the literature, which the authors describe as against the spirit of the task because those models have a global receptive field.([Section 4.1, p.7](https://arxiv.org/pdf/2008.07669v2#page=7 "With a test accuracy of 98.3%, HiPPO-LegS sets a true state-of-the-art accuracy on the permuted MNIST dataset."))
- **c7** Timescale shift (Character Trajectories, following Kidger et al.): test-time sampling rates or timestamps are changed relative to training; the authors state that all methods are near-perfect (>= 95%) without distribution shift, but that apart from HiPPO-LegS no method generalizes to unseen timescales.([Section 4.2, p.8](https://arxiv.org/pdf/2008.07669v2#page=8 "Though all methods achieve near-perfect accuracy (≥95%) without distribution shift, aside from HiPPO-LegS, no method is able to generalize to unseen timescales."))
- **c8** Speed: the fast LegS update, implemented in C++ with a PyTorch binding, performs 470,000 time-step updates per second on a single CPU core, stated as 10x faster than the LSTM and LMU; a footnote notes the LMU is only known to be fast with forward Euler discretization, not with bilinear/ZOH methods that this task requires to reduce numerical error.([Section 4.3, p.9](https://arxiv.org/pdf/2008.07669v2#page=9 "We implement the fast update in C++ with Pytorch binding and show in Table 3 that it can perform 470,000 time step updates per second on a single CPU core, 10x faster than the LSTM and LMU."))
