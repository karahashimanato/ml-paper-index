## 主張

出典のリンクは原論文PDFの該当ページを開く。リンクにカーソルを合わせると原文の引用が表示される。

- **c1** The paper draws on three years of experience as developers of lm-eval to document challenges and recommendations; the authors therefore discuss and promote their own library (stated in the abstract).([Abstract, p.1](https://arxiv.org/pdf/2405.14782v3#page=1 "In this paper we draw on three years of experience in evaluating large language models (LMs) as developers of the popular Language Model Evaluation Harness (lm-eval) (Gao et al., 2023) framework to provide guidance and lessons for the field moving forward."))
- **c2** The 'Key Problem': there can be many semantically equivalent but syntactically different ways of expressing the same idea, and assessing correctness would ideally require automatically detecting semantic equivalence, but the best automated tools for this are the very models being evaluated([Section 2.1, p.2](https://arxiv.org/pdf/2405.14782v3#page=2 "However, our best automated tools for determining whether two sentences are semantically equivalent are the very models we are seeking to evaluate."))
- **c3** Minor implementation details matter: citing prior work, the exact prompt string down to whitespace and the choice of few-shot examples can significantly change performance; in their Table 1 (0-shot, two common prompt styles on ARC-Challenge and MMLU) performance varies dramatically with the prompt (in some cases > 20%) and the best style varies by model, so prompt choice affects model rankings and conclusions.([Section 3.1, p.5](https://arxiv.org/pdf/2405.14782v3#page=5 "Thus, the selection of prompt affects the model rankings and research conclusions produced in addition to numeric scores themselves (Alzahrani et al., 2024)."))
- **c4** Benchmark-specific quirks: MMLU is correctly computed as a micro average over documents (as in the official script) rather than a macro average over the 57 subjects, a choice that affects results by several percentage points and is often unreported; ARC has a single 5-choice question among 4-choice ones; HumanEval has 3 documents lacking example tests.([Section 3.1, p.6](https://arxiv.org/pdf/2405.14782v3#page=6 "the choice of which affects results by several percentage points"))
- **c5** Scoring free-form answers: generated answers are typically extracted with regular expressions or other heuristics and scored by exact match, which the authors call often highly imperfect because models answer in varying formats and extraction can be biased toward models whose format resembles the original task; without the extraction code or model outputs it is difficult to separate format compliance from answer correctness (lm-eval provides a configurable Filter component).([Appendix B.4, p.28](https://arxiv.org/pdf/2405.14782v3#page=28 "Without knowledge of the extent to what extraction code is used, how it may be tailored to a model, or without access to model outputs, it is difficult to separate models’ compliance with the evaluation format from their answer correctness."))
- **c6** Format failure as a measurement artifact: GPT-NeoX-20B performs approximately randomly on ARC-C and MMLU with MMLU-style evaluation but much better with other formats, which exploratory analysis attributes to failing to follow the task and output format; on ARC-Easy it scores 72.4 ± 1.80% in the cloze setup vs 26.5 ± 1.78% MMLU-style.([Section 4.1, p.9](https://arxiv.org/pdf/2405.14782v3#page=9 "An even more extreme example is from ARC-Easy: using the “cloze” evaluation setup, GPT-NeoX achieves an accuracy of 72.4 ± 1.80% but using the MMLU-style setup it scores 26.5 ± 1.78%."))
- **c7** Uncertainty reporting: lm-eval reports bootstrapped standard errors by default; the authors note these bootstrap intervals address variation from sampling new questions from the same distribution, which differs from run-to-run variation of a stochastic model, and consider both, as well as variation across prompts and scoring systems, valuable.([Section 4.3, p.10](https://arxiv.org/pdf/2405.14782v3#page=10 "We report bootstrapped standard error metrics by default, making reporting of confidence intervals (as we have done in this paper) nearly as simple as copy-pasting an additional number into one’s paper."))
- **c8** Checklist recommendations: share exact prompts and full evaluation code, do not optimize prompts for a given model and disclose the amount of prompt engineering, avoid copying results from other papers unless the same code was verifiably used (clearly mark any copied numbers), provide model outputs, do qualitative analyses before scaling up, and perform statistical significance testing (e.g. averaging over multiple seeds or few-shot selections).([Appendix D, p.31](https://arxiv.org/pdf/2405.14782v3#page=31 "Results should not be copied or reported from other papers (Marie, 2022) whenever possible, unless one can verify that the same code has been used to run the experiments in those papers."))
