## 主張

出典のリンクは原論文PDFの該当ページを開く。リンクにカーソルを合わせると原文の引用が表示される。

- **c1** Mixtral has the same architecture as Mistral 7B except that each layer has 8 feedforward blocks (experts); for every token at each layer a router selects two experts and combines their outputs, and the selected experts can differ at each timestep, so each token has access to 47B parameters but uses only 13B active parameters during inference.([Abstract, p.1](https://arxiv.org/pdf/2401.04088v1#page=1 "As a result, each token has access to 47B parameters, but only uses 13B active parameters during inference."))
- **c2** Gating: the MoE output is the gate-weighted sum of expert outputs; among multiple alternatives for implementing the gate, the authors use a softmax over the Top-K logits of a linear layer, G(x) = Softmax(TopK(x Wg)), where non-top-K logits are set to minus infinity, so experts with zero gate need not be computed. Mixtral uses SwiGLU experts and K = 2.([Section 2.1, p.2](https://arxiv.org/pdf/2401.04088v1#page=2 "There are multiple alternative ways of implementing G(x) [6, 15, 35], but a simple and performant one is implemented by taking the softmax over the Top-K logits of a linear layer [28]."))
- **c3** Cost accounting: increasing the number of experts n with K fixed increases parameter count while keeping computational cost effectively constant, which motivates distinguishing the total (sparse) parameter count, growing with n, from the active parameter count used per token, growing with K up to n.([Section 2.1, p.3](https://arxiv.org/pdf/2401.04088v1#page=3 "This motivates a distinction between the model’s total parameter count (commonly referenced as the sparse parameter count), which grows with n, and the number of parameters used for processing an individual token (called the active parameter count), which grows with K up to n."))
- **c4** Difference from GShard: the formulation is similar to GShard except that Mixtral replaces all FFN sub-blocks by MoE layers (GShard replaces every other block) and GShard uses a more elaborate gating strategy for the second expert assigned to each token.([Section 2.1, p.3](https://arxiv.org/pdf/2401.04088v1#page=3 "This formulation is similar to the GShard architecture [21], with the exceptions that we replace all FFN sub-blocks by MoE layers while GShard replaces every other block, and that GShard uses a more elaborate gating strategy for the second expert assigned to each token."))
- **c5** Systems caveat: MoE layers can run on single GPUs with specialized kernels (e.g. Megablocks, which handles variable numbers of tokens per expert) or be distributed with Expert Parallelism, but EP introduces load-balancing challenges because the workload must be distributed evenly across GPUs to avoid overloading individual GPUs or computational bottlenecks.([Section 2.1, p.3](https://arxiv.org/pdf/2401.04088v1#page=3 "Note that EP introduces challenges in load balancing, as it is essential to distribute the workload evenly across the GPUs to prevent overloading individual GPUs or hitting computational bottlenecks."))
- **c6** Scope of the efficiency comparison with Llama 2: the analysis focuses on active parameter count (proportional to inference compute) and does not consider memory costs or hardware utilization; serving memory is proportional to the sparse parameter count (47B, still smaller than Llama 2 70B), and the SMoE layer adds overhead from routing and increased memory loads when running more than one expert per device, making it more suitable for batched workloads with good arithmetic intensity.([Section 3, p.4](https://arxiv.org/pdf/2401.04088v1#page=4 "Note that this analysis focuses on the active parameter count (see Section 2.1), which is directly proportional to the inference compute cost, but does not consider the memory costs and hardware utilization."))
- **c7** Evaluation protocol: Mixtral is compared to Llama models with all benchmarks re-run in the authors' own evaluation pipeline (commonsense reasoning 0-shot, world knowledge 5-shot, reading comprehension 0-shot, GSM8K/MATH with maj@8/maj@4, HumanEval/MBPP, MMLU, BBH, AGI Eval).([Section 3, p.3](https://arxiv.org/pdf/2401.04088v1#page=3 "We compare Mixtral to Llama, and re-run all benchmarks with our own evaluation pipeline for fair comparison."))
- **c8** Routing analysis: measuring the distribution of selected experts on subsets of The Pile validation set at layers 0, 15 and 31, the authors do not observe obvious topic-based patterns in expert assignment (e.g. ArXiv, PubMed Abstracts and PhilPapers look very similar); only DM Mathematics shows a marginally different distribution, which they consider likely a consequence of its synthetic nature.([Section 5, p.7](https://arxiv.org/pdf/2401.04088v1#page=7 "Surprisingly, we do not observe obvious patterns in the assignment of experts based on the topic."))
- **c9** Consecutive tokens are often assigned the same experts (positional locality), significantly more than random at higher layers; the authors note that high locality is more likely to over-subscribe certain experts under Expert Parallelism, while it can also be leveraged for caching (citing Eliseev and Mazur).([Section 5, p.8](https://arxiv.org/pdf/2401.04088v1#page=8 "For example, cases with high locality are more likely to cause over-subscription of certain experts when doing Expert Parallelism."))
