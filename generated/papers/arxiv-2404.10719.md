## 主張

出典のリンクは原論文PDFの該当ページを開く。リンクにカーソルを合わせると原文の引用が表示される。

- **c1** Theorem 4.1: with Pi_PPO the policies obtained by fitting a reward model on D and running PPO, and Pi_DPO the minimizers of the DPO loss, Pi_PPO is a proper subset of Pi_DPO; hence any PPO solution that exploits the reward model can also be found by DPO, and DPO may additionally find solutions exploiting out-of-distribution data.([Section 4.1, p.4](https://arxiv.org/pdf/2404.10719v3#page=4 "We have the following conclusion: ΠPPO is a proper subset of ΠDPO."))
- **c2** Counter-example and interpretation: with three actions and a preference dataset containing only y1 > y2, the DPO loss is minimized whenever the probability of y2 is 0, so DPO can put most mass on the unseen y3, which PPO cannot because pi_ref assigns y3 zero probability. The authors attribute reward misspecification to narrow preference-data coverage and argue that DPO suffers from it on OOD samples in a different manner, while PPO can use prompt-only data and the KL term regularizes generated samples.([Section 4.1, p.4](https://arxiv.org/pdf/2404.10719v3#page=4 "Specifically, DPO can develop a biased distribution favoring unseen responses, directly impacting quality of the learned policy."))
- **c3** Synthetic check (8 prompts x 8 responses, MLP policy and reward model, optimal responses on the diagonal, limited preference coverage): both DPO and the learned reward model assigned high values to responses outside the preference data; DPO's final model may assign them higher probability than the reference model, e.g. from 0.11 to 0.23 in the red-circled case, whereas PPO alleviated this with explicit KL regularization.([Section 4.2, p.5](https://arxiv.org/pdf/2404.10719v3#page=5 "For example, in the red circles, DPO increases the probability from 0.11 to 0.23."))
- **c4** Real data (SafeRLHF, Llama-2-7B, a combined safety-first preference): with SFT on Alpaca as base/reference, DPO gave only a 55.4% safety rate and low helpfulness, which the authors hypothesize is caused by distribution shift; using a reference further fine-tuned on safe SafeRLHF responses increased the safety rate by 16.4% and the helpfulness reward from -4.19 to -1.62. Helpfulness and harmfulness were measured with the official evaluation models, not used in training.([Section 4.3, p.5](https://arxiv.org/pdf/2404.10719v3#page=5 "As shown in Table 2, resolving the distribution shift issue essentially increases the safety rate by 16.4% and the helpfulness reward from −4.19 to −1.62."))
- **c5** Data sensitivity: filtering dual-unsafe and dual-safe pairs raised DPO's safety rate but filtering dual-safe pairs largely hurt helpfulness; iterative DPO (new responses from the model labeled by a learned reward model) reached a safety rate comparable to PPO but a much lower helpfulness reward. The authors suggest DPO may benefit from removing noise or controversies, but excessive discarding of high-quality data could hurt.([Section 4.3, p.5](https://arxiv.org/pdf/2404.10719v3#page=5 "These results suggest that while DPO may derive advantages from eliminating noise or controversies in the training data, excessively discarding high-quality data could be detrimental to DPO performance."))
- **c6** PPO key factors (ablation on HH-RLHF with Llama2-7B and APPS/CodeContest with CodeLlama-34B; implementation based on DeepSpeed-Chat with a scalar response-level reward and no auxiliary SFT loss): advantage normalization stabilized and improved PPO, a large batch size gave the most significant benefit especially on code generation, and an exponential-moving-average update of the reference model brought additional benefits. Baseline PPO with batch size 64 degraded performance on APPS relative to the SFT model.([Section 5, p.6](https://arxiv.org/pdf/2404.10719v3#page=6 "The most significant benefit is brought by using a large batch size, especially on code generation tasks."))
- **c7** Evaluation protocol on HH-RLHF: the OpenAssistant reward model (not used in training) plus GPT-4 pairwise comparisons with the DPO paper's prompt on 100 randomly sampled test queries; to reduce position bias, each pair is judged twice with positions swapped and inconsistent results are counted as a tie. A human evaluation with 4 persons per pair agreed with GPT-4 at rates of 60% and 61% (Appendix C.4).([Appendix B, p.14](https://arxiv.org/pdf/2404.10719v3#page=14 "If the results of the two evaluations are inconsistent, we set the final result as a “Tie”."))
- **c8** Code generation: PPO used a reward of 10 if generated code passed all training test cases and 0 otherwise, while DPO used iterative DPO (APPS) or correct/incorrect dataset solutions (CodeContest). On APPS, DPO-Iter failed to improve the SFT model at all model sizes despite nearly perfect test-case feedback; on CodeContest, after one epoch DPO reached a pass rate of 0 and output many meaningless code snippets, while PPO with CodeLlama-34B surpassed AlphaCode-41B (10@1k from 16.4% to 22.4%, stated in the Introduction).([Section 6, p.8](https://arxiv.org/pdf/2404.10719v3#page=8 "After one epoch of training, the code written by the DPO model has achieved a pass rate of 0, we observe that the DPO model outputs many meaningless code snippets."))
- **c9** Stated limitations: the reward model is significant for both PPO and DPO-Iter, but the paper does not study how to train a robust reward model; for the code competition tasks the ground-truth (test-case) reward is used for PPO training and for labeling DPO-Iter data, which the authors say does not affect their conclusions.([Section 7, p.9](https://arxiv.org/pdf/2404.10719v3#page=9 "For the code competition task, we utilize the ground-truth reward for PPO training and the labeling of DPO-Iter."))
