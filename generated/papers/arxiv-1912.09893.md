## 主張

出典のリンクは原論文PDFの該当ページを開く。リンクにカーソルを合わせると原文の引用が表示される。

- **c1** Risk assessment (model assessment): k-fold CV uses k training/test splits, and for each split an internal model selection picks hyperparameters using the training data only, so test data is never used for model selection; because each split may select a different configuration, the estimate refers to the performance of a class of models.([Section 3, p.3](https://arxiv.org/pdf/1912.09893v3#page=3 "This way, test data is never used for model selection."))
- **c2** Model selection (hyperparameter tuning on a validation set or inner split) gives biased, generally over-optimistic estimates of generalization (citing Cawley & Talbot, 2010); the authors state that clearly separating model selection and model assessment estimates is their main contribution and is lacking or ambiguous in the reviewed literature.([Section 3.2, p.3](https://arxiv.org/pdf/1912.09893v3#page=3 "Consequently, model selection results are generally over-optimistic; this issue is thoroughly documented in Cawley & Talbot (2010)."))
- **c3** Review of DGCNN, DiffPool, ECC and GIN (based solely on the papers and available code at submission time): model-selection code is not provided for any of them; GIN, as stated in its paper and review discussion, reports validation accuracy of 10-fold CV; for DiffPool it is unclear whether results are on a test set, and its splits are random without a seed; ECC reports no standard deviations; DGCNN tunes learning rate and epochs on one fold only.([Section 4, p.4](https://arxiv.org/pdf/1912.09893v3#page=4 "In other words, reported results refer to model selection and not to model evaluation."))
- **c4** Experimental setting: 10-fold CV for assessment, an inner 90%/10% holdout for selection, then three training runs on the whole training fold (each holding out a random 10% for early stopping) averaged to smooth unfavorable initializations; all splits are pre-computed and stratified. Grid search over 32 to 72 configurations per model (always including those used by the original authors), more than 47000 training runs in total, with a 72-hour limit per training.([Experiments, p.6](https://arxiv.org/pdf/1912.09893v3#page=6 "Our experimental approach is to use a 10-fold CV for model assessment and an inner holdout technique with a 90%/10% training/validation split for model selection."))
- **c5** Features: all models get the same node features - one-hot atom types for chemical datasets (plus 18 available features on ENZYMES) and, for social datasets without features, either an uninformative constant feature or the node degree. The authors note that GIN's one-hot degree features trade improved performance for inability to generalize to graphs with arbitrary node degree.([Experiments, p.5](https://arxiv.org/pdf/1912.09893v3#page=5 "In general, good experimental practices suggest that all models should be consistently compared to the same input representations."))
- **c6** Baselines that ignore topology: if a GNN performs close to a structure-agnostic baseline, either the task does not need topology or the GNN is not exploiting structure adequately; the latter is harder to assess (training data size, inductive bias, hyperparameters), while significant improvements over the baseline are a strong indicator that topology has been exploited.([Experiments, p.5](https://arxiv.org/pdf/1912.09893v3#page=5 "As a matter of fact, if GNN performances are close to the ones of a structure-agnostic baseline, one can draw two possible conclusions: the task does not need topological information to be effectively solved, or the GNN is not exploiting graph structure adequately."))
- **c7** Results: on D&D, PROTEINS and ENZYMES none of the five GNNs improves over the structure-agnostic baseline, while on NCI1 the baseline is clearly outperformed; an over-parameterized baseline (10000 hidden units, no regularization) reaches around 67% training accuracy on NCI1 whereas GIN can easily overfit (≈100%). The authors suggest that small gains on these datasets are likely caused by other factors such as random initialization rather than exploiting structure.([Results and Discussion, p.7](https://arxiv.org/pdf/1912.09893v3#page=7 "Importantly, we discover that on D&D, PROTEINS and ENZYMES none of the GNNs are able to improve over the baseline."))
- **c8** Node degree on social datasets: adding degrees as features is almost always beneficial, enough for the baseline to improve by ≈15% and achieve the best result on IMDB-BINARY, and it drastically changes the model ranking; it matters less for most GNNs except DGCNN; across folds the median number of layers drops by ≈1 (GraphSAGE excepted), which the authors say 'may be due to' architectures computing the degree in the first layer.([Results and Discussion, p.7](https://arxiv.org/pdf/1912.09893v3#page=7 "Based on our results, using node degrees as input features is almost always beneﬁcial to increase performances on social datasets, sometimes by a large amount."))
