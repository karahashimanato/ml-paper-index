## 主張

出典のリンクは原論文PDFの該当ページを開く。リンクにカーソルを合わせると原文の引用が表示される。

- **c1** The authors argue that prior work focused almost exclusively on CASH and that, since this search is typically intractable (nonconvex/nonsmooth), CASH algorithms are expensive, spending significant compute on poor configurations.([Section 1, p.1](https://arxiv.org/pdf/2003.06505v1#page=1 "Their brute-force search expends signiﬁcant compute evaluating poor model/hyperparameter conﬁgurations that no reasonable data scientist would consider."))
- **c2** Stacking design: whereas traditional stacking uses simpler stacker models to avoid another CASH problem, AutoGluon reuses all base-layer model types with the same hyperparameter values as stackers; the stackers take the original features concatenated with lower-layer predictions, and the final layer aggregates stackers with ensemble selection (citing Caruana et al., 2004).([Section 2.5, p.4](https://arxiv.org/pdf/2003.06505v1#page=4 "AutoGluon instead simply reuses all of its base layer model types (with the same hyperparameter values) as stackers."))
- **c3** Caveat of k-fold bagging: higher layers must be trained only on out-of-fold (OOF) predictions, but OOF predictions can still be slightly overfit because training of some models is influenced by OOF data (e.g. through the early-stopping criterion), and a stacker trained on overfit lower-layer predictions may amplify this through the layers; repeated k-fold bagging on n random partitions is proposed to mitigate it.([Section 2.6, p.4](https://arxiv.org/pdf/2003.06505v1#page=4 "While k-fold bagging efﬁciently reuses training data, it remains susceptible to a subtle form of over-ﬁtting."))
- **c4** In the benchmark, AutoGluon's hyperparameter_tune option was not used (auto_stack=True, 2-layer stacking with repeated bagging within the time limit); the authors state this demonstrates for the first time that high-accuracy AutoML is achievable entirely without CASH.([Section 4.1, p.7](https://arxiv.org/pdf/2003.06505v1#page=7 "This demonstrates for the ﬁrst time that high-accuracy AutoML is achievable entirely without CASH."))
- **c5** The default hyperparameter values of AutoGluon's models were chosen a priori and not tuned on the datasets used for benchmarking in the paper (they are in the AutoGluon source code); the neural network's layer sizes are scaled adaptively to the data in a fixed manner rather than by hyperparameter optimization.([Appendix A, p.11](https://arxiv.org/pdf/2003.06505v1#page=11 "These default hyperparameter values were chosen a priori and not tuned based on the particular datasets used for benchmarking in this paper."))
- **c6** Benchmark protocol: 39 OpenML AutoML Benchmark datasets (Gijsbers et al., 2019), each with the original 10 train/test splits (390 problems), 1h and 4h limits, loss 1-AUC (binary) or log-loss (multi-class), scored with the original benchmark code on an AWS m5.2xlarge (8 vCPU, 32 GiB) as in the original benchmark; plus 11 Kaggle competitions scored by Kaggle's server on hidden labels (4h and 8h, m5.24xlarge with 96 vCPU, 384 GiB). Averages and counts are taken only over datasets where all frameworks ran without error.([Section 4.1, p.6](https://arxiv.org/pdf/2003.06505v1#page=6 "Each AutoML framework is extensively evaluated in this benchmark through replicate runs on 10 different training/test splits for each dataset, making 390 prediction problems in total (splits provided by original benchmark, and reported numbers are averaged over them)."))
- **c7** Baseline configuration: Auto-WEKA, auto-sklearn, TPOT, H2O AutoML and GCP-Tables were run with default settings except where package authors suggested improvements in private communication; Auto-WEKA, TPOT and auto-sklearn were given data preprocessed by AutoGluon's own pipeline (Appendix C), and all frameworks ran on the same EC2 instance type with identical time limits except GCP-Tables (92 Google Cloud servers by default); actual training times are reported because some frameworks only loosely respected the limits.([Section 4.1, p.6](https://arxiv.org/pdf/2003.06505v1#page=6 "Each was run with default settings except where the package authors suggested an improved setting in private communication."))
- **c8** Because running GCP-Tables on all 390 AutoML Benchmark problems was economically infeasible (4h runs would exceed $30k), it was run only on the first fold of each of the 39 datasets, and comparisons with AutoGluon use only that fold.([Appendix C, p.13](https://arxiv.org/pdf/2003.06505v1#page=13 "Because running GCP-Tables on all 390 prediction problems of the AutoML benchmark was economically infeasible (4h runs would total over $30k), we only ran this AutoML tool on the ﬁrst fold of each of the 39 datasets."))
